## 上传页面

选择“手动上传代码包 / 压缩包”，使用 `deploy/waiqi-cloudrun-时间.zip`。
ZIP 根目录包含 Dockerfile，没有额外一层项目目录。
若平台不能提供有效构建错误日志，优先用预构建包：
`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package-cloud.ps1 -Prebuilt`。
该模式本地构建前端，用 esbuild 打包后端及 MySQL 工作线程；Dockerfile 只拉取 Node 24
镜像并复制 runtime/server 和 runtime/dist，云端不执行 npm/pnpm 安装。
用 `node scripts/verify-cloud-runtime.mjs deploy/cloudrun-时间/runtime` 在项目外临时目录验证，
避免本机 node_modules 掩盖遗漏依赖；此验证不等于 Linux Docker 或真实云端联调。
ZIP 使用标准正斜杠路径，兼容 Linux 解压。
端口 80；目标目录留空（根目录）；Dockerfile 有；名称 Dockerfile；灰度发布关闭。
环境变量不在截图中的高级设置里，需在服务设置或下一步发布配置中找到实际入口。
填写 `cloud.env.example` 中的变量，密码、AppSecret 和模型密钥只在控制台录入。
用户当前控制台保存服务设置会触发当前镜像重新发布；发布失败后配置不保留。
新部署包支持配置等待模式：先上传本应用 ZIP 替换示例，不要求先在旧示例上保存配置。
缺少数据库、管理员或存储配置时，进程监听 80，但业务接口全部返回 503，
`/api/health` 返回 HTTP 200 且 `ok:false,status:configuration_required`，列出缺少的变量名称。
初始化失败（例如数据库连接失败）也维持诊断服务，状态为 initialization_failed；不会开放业务。
容器发布成功仅说明诊断进程可运行；必须完成真实配置后看到正常健康状态，才能开始业务联调。
替换成功后修改环境变量，控制台重新发布的是我们的程序，不再依赖官方示例能够启动。
如果需要继续运行官方示例，仍须保留 MYSQL_ADDRESS 和 MYSQL_USERNAME；它们不影响新程序。
不要上传项目根目录的 .env、data、node_modules 或备份。

## 数据与实例

容器以 `0.0.0.0:80` 启动；运行时只使用 MySQL 和 COS，缺少配置会停止启动，不会回退 SQLite。
MySQL 主机 `10.19.111.70`，3306，数据库 `waiqi_english`。启动自动建四张业务表，不删除既有表。
暂用已有 root 账号联调；后续可以替换为仅该数据库授权的业务账号。
本地 SQLite、音频和 .env 保持原样，历史数据不会自动上传到云端。

当前应用后台任务仍是单实例模型。实例最小数和最大数均设 1，不启用缩容至零。
数据库用会话锁防止第二实例启动后破坏旧实例的生成任务、产生重复收费。
新版本遇到旧实例持锁时先启动配置/诊断 HTTP 服务，状态为 waiting_for_previous_instance，
每 5 秒重试一次。旧实例退出并释放数据库锁后，在同一 HTTP 端口自动开放业务。
等待期间业务接口返回 503；初始化认证错误不会被当成锁冲突自动重试。
如果平台仍保留旧业务版本的运行实例，需要在控制台停止旧实例后才能完成交接；
不能关闭整个服务或删除数据库。不支持多实例业务并发和无停机升级。
数据库驱动通过工作线程衔接原有同步事务；查询串行且有超时，适用于当前小规模联调。
扩容前需要改成异步查询、任务租约与分页，而不是单纯增加实例数量。

## 微信登录、模型与隐私

正式小程序包改用 `wx.cloud.callContainer`，测试登录关闭，登录仍由服务端校验微信登录 code，
不信任自行传入的 OpenID 或任意 HTTP 头。需要服务端 WECHAT_APP_SECRET。
开启开放接口服务后，云调用会使用容器内证书。Dockerfile 已设置 `NODE_EXTRA_CA_CERTS=/app/cert/certificate.crt`，使 Node 的 HTTPS 微信登录请求信任官方云调用代理证书；不关闭 TLS 验证。网络失败会返回脱敏错误码，便于区分证书、网络与微信凭据问题，仍需真机验证。
首次隐私同意页展示简要用途与 AI 说明，完整政策默认折叠，用户可展开后勾选同意；从「我的 → 隐私政策」可再次查看全文。完整政策仍保留真实运营者与联系方式。
在控制台关联正式小程序与该云环境，确认云调用权限。
聊天、记忆和 TTS 供应商配置从本地配置手动迁入控制台，不打入 ZIP。
云托管包默认 `CONTENT_SAFETY_PROVIDER=wechat-cloudrun`，直接调用微信官方文本安全接口 v2。先在云托管控制台「云调用」开启「开放接口服务」，将 `/wxa/msg_sec_check` 加入微信令牌权限列表，再上传新包创建版本（开关对已有版本不会补生效）。无需填写 CONTENT_SAFETY_URL 或 CONTENT_SAFETY_KEY。
聊天输入、回复及英语便签、翻译输入/输出均检查；只接受 pass，review/risky 阻止显示，接口异常也不放行。身份来自服务器登录验证后存储的用户 OpenID，用户需在近两小时访问小程序。长文本按 2400 字符分段并重叠100字符，避免超限；分段审核不能保证跨段语义判断，未上架接口仅100次/天，避免大量反复测试。
后台语料/TTS无真实小程序用户身份，微信模式下会明确阻止，不伪造 OpenID。以后启用语料生产应接入独立审核服务。保留通用审核模式：显式设置 CONTENT_SAFETY_PROVIDER=compatible，并配置 CONTENT_SAFETY_URL（POST {text} 返回 {allowed:true}）及可选 CONTENT_SAFETY_KEY。健康接口 safety=true 只表示已选择适配器，不证明权限与真实调用成功。
首次上线保留 PRIVACY_POLICY_CONFIRMED=false；在后台补齐实际主体、服务商、用途、保留期限、
删除/注销及联系方式等隐私信息后再设 true。不要把“本地内测”的默认文案当正式隐私政策。

## 联调验收

1. 构建和启动成功；`/api/health` 显示 mysql / cos / devLogin false。
2. 正式 AppID 的开发者工具导入 `deploy/miniprogram-cloud-时间`，使用云调用访问健康接口。
3. 填完微信凭据、内容安全和真实隐私说明后，检查登录和两位用户的记录隔离。
4. 检查聊天、翻译、后台语料、TTS 上传、发布和手机播放。
5. 重启容器后验证聊天、语料和音频保存；数据库锁在旧实例停止后释放。
6. 完成小程序备案、适用 AI 类目材料、隐私申报和真机测试后，再提交微信审核。

该代码包用于云端联调，不代表已经部署成功或已满足正式版审核要求。
